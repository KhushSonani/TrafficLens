## 1. MERN Overview
The backend architecture implements the M (MongoDB), E (Express.js), and N (Node.js) layers of the MERN stack. It acts strictly as a data-serving layer, ingesting the `predictions.csv` generated by Student 2's Random Forest and serving it downstream to the React frontend (R) planned for future tasks.

## 2. Node.js & Express Role
Node.js provides the asynchronous runtime environment, while Express handles API routing, JSON parsing, CORS setup, and HTTP status codes.

## 3. MongoDB & Mongoose Role
MongoDB serves as the NoSQL document store, providing scalable O(1) reads for traffic data. Mongoose provides the strict Object Data Modeling (ODM) layer to enforce the specific prediction schemas output by the ML phase.

## 4. React Role (Planned)
React will be initialized in future tasks to consume `/api/predictions` and MapReduce analytics routes to visualize the data natively.

## 6. Environment Variables
- `PORT`: (Default `5000`) Defines the Express listener port.
- `MONGODB_URI`: Connection string to MongoDB (Default `mongodb://localhost:27017/trafficlens`).
- `PREDICTIONS_CSV_PATH`: Defines the path to Student 2's ML output.

## 7. MongoDB Configuration
- **Database**: `trafficlens`
- **Collection**: `predictions`
- **Compound Unique Key**: `{ sensor_id: 1, timestamp: 1 }`. This explicitly guarantees that duplicate ingestion runs will upsert existing predictions without duplicating rows.

## 8. Prediction Schema
Enforced via Mongoose:
- `timestamp`: Date (Required)
- `sensor_id`: Number (Required)
- `actual_congestion`: String enum `['LOW', 'MEDIUM', 'HIGH']`
- `predicted_congestion`: String enum `['LOW', 'MEDIUM', 'HIGH']`
- `probability_high`: Number `[0,1]`
- `probability_low`: Number `[0,1]`
- `probability_medium`: Number `[0,1]`

## 9. Prediction Ingestion
A robust standalone node script `scripts/importPredictions.js` uses stream-based CSV parsing (`csv-parser`) to efficiently map the raw CSV to the Mongoose ODM and execute an idempotency-safe `$set` with `{ upsert: true }`.
