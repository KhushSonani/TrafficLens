## 1. Purpose
The purpose of this pipeline is to transform the validated S2-1 prepared traffic dataset into an ML-ready feature dataset. It creates temporal features and historical traffic features needed for downstream supervised ML tasks (S2-3 Congestion Classification and S2-4 Random Forest).

No models are trained or evaluated in this stage.

---

## 2. Input Dataset
**File:** `output/ml_prepared_traffic.csv`

Generated by the S2-1 pipeline, this file contains the cleaned output from the Student 1 Hadoop analytics jobs.

## 3. Input Schema
- `timestamp`: string (`YYYY-MM-DD HH`)
- `sensor_id`: int
- `reference_speed`: float
- `current_speed`: float
- `congestion_score`: float
- `congestion_class`: string (`LOW`, `MEDIUM`, `HIGH`)

---

## 4. Feature Definitions

- `sensor_id`: Integer identifier for the loop-detector sensor (preserved).
- `hour`: Hour of the day, derived from timestamp (0 to 23).
- `day_of_week`: Day of the week, derived from timestamp (0=Monday, 6=Sunday).
- `is_weekend`: Binary flag (1 if Saturday/Sunday, else 0).
- `current_speed`: The hourly mean speed (mph) from the input (preserved).
- `previous_speed`: The `current_speed` from the immediately preceding hour for the SAME sensor.
- `rolling_average`: The mean `current_speed` over a 3-hour rolling window (including the current observation and up to 2 previous observations) for the SAME sensor.
- `congestion_score`: Preserved from S1-6.
- `congestion_class`: Preserved from S1-6 (target label).

---

## 5. Timestamp Handling
The `timestamp` string is parsed into a pandas `datetime` object (`%Y-%m-%d %H`). This ensures correct chronological sorting before temporal features are generated.

## 6. Hour Calculation
Extracted programmatically using `timestamp.dt.hour`. Ranges from `0` (midnight) to `23` (11 PM).

## 7. Day-of-week Calculation
Extracted programmatically using `timestamp.dt.dayofweek`. Follows the convention: `0 = Monday`, `6 = Sunday`.

## 8. Weekend Calculation
Calculated as `1` if `day_of_week >= 5` (Saturday or Sunday), else `0`.

## 9. Previous-speed Methodology
Calculated by grouping the dataset by `sensor_id` and using the `shift(1)` operation on `current_speed`. Because the data is strictly sorted chronologically within each sensor group beforehand, this guarantees that `previous_speed` is the immediately preceding hour's speed for that specific sensor.

## 10. Rolling-average Methodology
Calculated by grouping the dataset by `sensor_id` and applying a rolling window of size 3 to the `current_speed`.
- Minimum periods = 1.
- Window includes the current observation and up to 2 past observations.
- E.g. at $t_3$, the average is over $(t_1, t_2, t_3)$. At $t_2$, it is over $(t_1, t_2)$.
- No future observations are ever included in the window.

## 11. Sensor-boundary Handling
Before calculating any temporal features (previous speed, rolling average), the data is strictly sorted by `['sensor_id', 'timestamp']`. All temporal shifting and rolling operations are applied via a `groupby('sensor_id')` to ensure that data from Sensor A can never leak into the feature calculation for Sensor B.

## 12. Missing-value Handling
Because `previous_speed` requires a preceding observation, the chronologically first record for each of the 207 sensors will result in a `NaN` for `previous_speed`. 
- **Action:** These records with missing `previous_speed` are dropped.
- **Affected:** Exactly 207 records (one for each unique sensor).
- **Justification:** Dropping these ensures a clean dataset without fabricating or arbitrarily imputing fake previous speeds, and it satisfies downstream algorithms like Scikit-Learn's Random Forest which historically cannot handle NaNs. `rolling_average` handles its initial values natively via `min_periods=1`.

## 13. Leakage-prevention Strategy
- Data is strictly sorted temporally.
- Backward shifting (`shift(1)`) explicitly prevents future values from becoming `previous_speed`.
- `rolling(window=3)` is trailing by default in pandas; no centered or forward windows are used.
- Target variables (`congestion_score`, `congestion_class`) are NOT used to derive any features.
